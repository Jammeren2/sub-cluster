# concord-sub-mirror

Зеркало и **агрегатор** VPN-подписок с веб-панелью. Поднимает у тебя на
сервере HTTP-сервис, который:

1. **Зеркалит** подписку — ходит на оригинальную подписку с заголовками
   клиента Happ и отдаёт тот же JSON вместе со всеми заголовками
   (`Subscription-Userinfo`, `Profile-Title`, `Profile-Update-Interval` …).
   Твоя ссылка становится полноценной заменой оригинальной.

2. **Сливает несколько подписок в одну.** В веб-панели создаёшь маршрут
   (например `/custom/custom`), указываешь ему несколько upstream-ссылок и
   своё название — сервис сходит на каждую, вытащит все ноды
   (vless / vmess / trojan / ss / …), объединит их без дублей и отдаст
   одной подпиской с агрегированным счётчиком трафика.

3. Даёт **веб-панель** управления маршрутизированием с авторизацией
   (логин/пароль из переменных окружения).

Само приложение (`sub_server.py`) — на чистой стандартной библиотеке Python,
без зависимостей. Docker нужен лишь для удобного деплоя.

---

## Веб-панель

Доступна по пути `ADMIN_PATH` (по умолчанию `/admin`), вход по
`ADMIN_USER` / `ADMIN_PASSWORD`. В панели можно:

- создавать маршруты (свой путь + название);
- задавать список upstream-ссылок (по одной в строке) — они сольются в одну;
- переименовывать подписку (название видно в клиенте);
- менять путь, включать/выключать и удалять маршруты;
- выбирать режим: **слияние** (несколько → одна, base64-список ссылок) или
  **зеркало** (один upstream отдаётся как есть, с его заголовками).

### Пример: слить два ключа в один

```
https://server.example.net:2096/sub/REDACTED-TOKEN
https://203.0.113.10:2096/sub/REDACTED-TOKEN
```

→ создаёшь маршрут с путём `/custom/custom`, режим **слияние**, вставляешь обе
ссылки и пишешь название. Готовая подписка:

```
https://твой-домен/custom/custom
```

## Деплой на сервере

Параметры задаются в `docker-compose.yml` через `${VAR:-значение}` или
переменной окружения при запуске (предпочтительно для секретов).

```bash
git clone <твой-репозиторий> concord-sub-mirror
cd concord-sub-mirror
ADMIN_USER=admin ADMIN_PASSWORD='длинный-секрет' docker compose up -d --build
docker compose logs -f
```

Приложение слушает порт **2347**. Домен/HTTPS навешиваешь сам сверху
(nginx/Caddy/туннель) на `http://127.0.0.1:2347`. Конфиг маршрутов хранится
в `./data/config.json` (volume) — переживает пересоздание контейнера.

Открой панель: `http://твой-домен/admin`.

## Настройки (переменные окружения)

| Переменная       | Назначение                                                            |
|------------------|----------------------------------------------------------------------|
| `ADMIN_USER`     | Логин веб-панели (по умолчанию `admin`)                              |
| `ADMIN_PASSWORD` | **Пароль** веб-панели — обязательно поменять                          |
| `ADMIN_PATH`     | Путь панели (по умолчанию `/admin`)                                  |
| `CONFIG_FILE`    | Файл конфига маршрутов (в Docker — `/data/config.json`)              |
| `HOST_PORT`      | Порт на хосте (по умолчанию `2347`)                                  |
| `CACHE_TTL`      | Кэш ответа upstream, сек (по умолчанию 60)                           |
| `HAPP_HWID`      | HWID клиента Happ (обычно менять не нужно)                           |
| `INSECURE_TLS`   | `1` — отключить проверку TLS (крайний случай)                        |
| `UPSTREAM_URL` + `SUB_PATH` | Необязательно: если заданы оба, при **первом** запуске создаётся маршрут-зеркало (легаси-совместимость) |
| `PROFILE_TITLE`  | Название для легаси-зеркала                                          |

> ⚠️ Маршруты и их пути хранятся в `./data/config.json` (в `.gitignore`).
> Пути подписок — это, по сути, пароли к ним: не публикуй их.

## Управление

```bash
docker compose up -d --build   # пересобрать и перезапустить
docker compose down            # остановить
docker compose logs -f         # логи (в т.ч. устройства, обращающиеся к подписке)
```

Здоровье сервиса: `GET /healthz` → `ok` (используется в Docker healthcheck).

## Как это работает

```
Клиент ──GET /custom/custom──► твой сервер ──┬─GET (заголовки Happ)─► upstream A
                                             └─GET (заголовки Happ)─► upstream B
Клиент ◄── base64-список всех нод + агрегированный трафик ◄── твой сервер
```

- Ответы upstream кэшируются (по умолчанию 60 сек) — клиенты опрашивают часто.
- gzip от upstream распаковывается; ноды извлекаются из JSON-конфига Happ/xray,
  base64-списка или обычного текста.
- В режиме «слияние» ноды объединяются без дублей, считается суммарный трафик
  (`Subscription-Userinfo`) и подставляется твоё название (`Profile-Title`).
- В режиме «зеркало» ответ upstream отдаётся как есть со всеми его заголовками.
