# concord-sub-mirror

Зеркало (прокси) VPN-подписки. Поднимает у тебя на сервере HTTP-эндпоинт,
который по своей ссылке ходит на оригинальную подписку с заголовками клиента
Happ и отдаёт тот же JSON вместе со всеми заголовками подписки
(`Subscription-Userinfo`, `Profile-Title`, `Profile-Update-Interval` и т.д.).

Твоя ссылка становится полноценной заменой оригинальной — её можно вставить
в Happ/любой клиент, и он увидит те же ноды, тот же трафик и срок.

Само приложение (`sub_server.py`) — на чистой стандартной библиотеке Python,
без зависимостей. Docker нужен лишь для удобного деплоя.

---

## Деплой на сервере

Все параметры заданы прямо в `docker-compose.yml` в виде `${VAR:-значение}`.
Менять их можно двумя способами:

1. **Отредактировать значения по умолчанию** прямо в `docker-compose.yml`
   (после `:-`), или
2. **Передать переменной окружения** при запуске — она перебьёт значение по
   умолчанию (см. примеры ниже). Этот способ предпочтительнее для секрета.

```bash
git clone <твой-репозиторий> concord-sub-mirror
cd concord-sub-mirror
SUB_PATH=/s/ТВОЙ-СЕКРЕТ docker compose up -d --build
docker compose logs -f
```

Приложение слушает порт **2347**. Домен/HTTPS навешиваешь сам сверху
(nginx/Caddy/туннель) на `http://127.0.0.1:2347`.

Проверка:
```bash
curl -D - http://127.0.0.1:2347/s/ТВОЙ-СЕКРЕТ
```

## Настройки (в `docker-compose.yml`)

| Переменная     | Назначение                                                        |
|----------------|-------------------------------------------------------------------|
| `UPSTREAM_URL` | Оригинальная подписка, которую дублируем                          |
| `SUB_PATH`     | **Секретный** путь твоей подписки (пароль к ней) — обязательно поменять |
| `PROFILE_TITLE`| Своё название подписки в Happ. Пусто = оригинальное (Concord)     |
| `CACHE_TTL`    | Кэш ответа upstream, сек (по умолчанию 60)                        |
| `HOST_PORT`    | Порт на хосте (по умолчанию `2347`); можно `127.0.0.1:2347`      |
| `HAPP_HWID`    | HWID клиента Happ (обычно менять не нужно)                        |
| `INSECURE_TLS` | `1` — отключить проверку TLS (крайний случай)                     |

> ⚠️ Если впишешь свой секретный `SUB_PATH` прямо в `docker-compose.yml` и
> запушишь в **публичный** репозиторий — секрет утечёт. Для публичного репо
> оставь в файле заглушку `/s/CHANGE-ME`, а реальный путь передавай переменной
> окружения при запуске (`SUB_PATH=... docker compose up -d`).

## Управление

```bash
docker compose pull            # если используешь готовый образ
docker compose up -d --build   # пересобрать и перезапустить
docker compose down            # остановить
docker compose logs -f         # логи
```

Здоровье сервиса: `GET /healthz` → `ok` (используется в Docker healthcheck).

## Как это работает

```
Happ ──GET /s/секрет──► твой сервер ──GET с заголовками Happ──► sub.by-concord.pro
Happ ◄── JSON + заголовки подписки ◄── твой сервер ◄── JSON (gzip) ◄──┘
```

- Ответ upstream кэшируется (по умолчанию 60 сек) — клиенты опрашивают часто.
- gzip от upstream распаковывается, клиенту отдаётся готовый JSON.
- Заголовки подписки (`Subscription-Userinfo`, `Profile-Title`, …) пробрасываются как есть.
