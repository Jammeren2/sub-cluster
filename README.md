# sub-cluster (бывш. concord-sub-mirror)

Кластер из 3+ узлов, который отдаёт VPN-подписки и сам переживает падение
любого сервера за счёт **DNS-фейловера через reg.ru**.

Каждый узел:
- отдаёт подписки (зеркало одной или **слияние нескольких** в одну, base64-список);
- хранит конфиг в локальной **SQLite** и **синхронизирует** его с другими узлами;
- пингует остальных, понимает, кто живой, и при падении активного **самый живой
  по приоритету** узел переписывает A-записи доменов на себя через API reg.ru;
- даёт веб-панель: нодовый граф подписок, список узлов с живостью, ручное
  переключение DNS, настройки reg.ru/доменов/фейловера.

Домены:
- **admin.example.net** — веб-панель;
- **happ.example.com** — подписки для клиентов.

Оба всегда указывают на один активный узел; при фейловере переезжают вместе.

---

## Архитектура

```
            ┌─ admin.example.net ─┐        ┌─ happ.example.com ─┐
            ▼  (reverse-proxy:443)  ▼        ▼  (reverse-proxy)  ▼
        ┌──────────────── активный узел ────────────────┐
        │  ADMIN :8080   SUB :8081   CLUSTER :8083       │
        └───────────────────┬───────────────────────────┘
        peer-API (HMAC) :8083│  опрос живости + синк конфига (SQLite, LWW)
        ┌───────────────┐    │    ┌───────────────┐
        │   узел 2       │◄───┴───►│   узел 3       │
        └───────────────┘         └───────────────┘
   активный мёртв → самый живой по приоритету ставит себя в оба домена (reg.ru API)
```

Три порта на узле:
- **ADMIN_PORT (8080)** — панель (за доменом admin.example.net);
- **SUB_PORT (8081)** — подписки (за доменом happ.example.com);
- **CLUSTER_PORT (8083)** — peer-API кластера, узлы ходят сюда друг к другу
  по публичному IP (запросы подписаны HMAC через `CLUSTER_SECRET`).

## Переменные окружения (на каждом узле)

| Переменная        | Назначение                                                         |
|-------------------|--------------------------------------------------------------------|
| `NODE_ID`         | Уникальный id узла (разный на каждом сервере)                       |
| `NODE_LABEL`      | Человеческая метка (видна в панели)                                 |
| `NODE_PUBLIC_IP`  | Публичный IP сервера — **его прописываем в DNS** при фейловере       |
| `NODE_PRIORITY`   | Приоритет (меньше = важнее). Активным становится самый живой с наименьшим |
| `PEERS`           | `ip:8083,ip:8083` других узлов — для бутстрапа (дальше синк сам)    |
| `CLUSTER_SECRET`  | Секрет подписи peer-запросов — **одинаковый на всех узлах**         |
| `SECRET_KEY`      | Ключ шифрования секретов в БД — **одинаковый на всех узлах**        |
| `ADMIN_USER` / `ADMIN_PASSWORD` | Доступ в панель                                      |
| `ADMIN_PORT` / `SUB_PORT` / `CLUSTER_PORT` | Порты (8080/8081/8083)                  |
| `DB_FILE`         | Путь к SQLite (в Docker — `/data/cluster.db`, volume)              |
| `CACHE_TTL`       | Кэш ответов upstream, сек (60)                                      |

reg.ru-логин/пароль и домены задаются в панели (`/settings`) **один раз** и
расходятся по кластеру (пароль шифруется `SECRET_KEY`, поэтому ключ должен
совпадать на всех узлах).

## Деплой

Два compose-файла: `docker-compose.yml` — для Coolify (только приложение,
HTTPS делает прокси Coolify), `docker-compose.standalone.yml` — для серверов
без Coolify (приложение + Caddy).

### Узел с Coolify

Coolify сам поднимает прокси (Traefik) на 80/443, поэтому свой Caddy там не
нужен — деплоится только сервис `app` из `docker-compose.yml`.

1. Создай ресурс **Docker Compose** из этого репозитория (файл по умолчанию
   `docker-compose.yml`).
2. В **Environment Variables** задай: `NODE_ID`, `NODE_LABEL`, `NODE_PUBLIC_IP`,
   `NODE_PRIORITY`, `PEERS` (адреса других узлов `ip:8083`), `CLUSTER_SECRET`,
   `SECRET_KEY`, `ADMIN_USER`, `ADMIN_PASSWORD` (см. `.env.example`).
3. Назначь домены сервису `app`:
   `admin.example.net` → порт **8080**, `happ.example.com` → порт **8081**
   (в Coolify: Domains у сервиса, или переменные `SERVICE_FQDN_APP_8080` /
   `SERVICE_FQDN_APP_8081`). HTTPS Coolify выпустит, когда домен укажет на узел.
4. Порт **8083** уже публикуется на хост (peer-API) — убедись, что он открыт
   снаружи для других узлов.

### Узлы без Coolify (docker compose + Caddy)

```bash
git clone <репозиторий> sub-cluster && cd sub-cluster
cp .env.example .env      # заполни NODE_ID/NODE_PUBLIC_IP/PEERS/секреты
docker compose -f docker-compose.standalone.yml up -d --build
docker compose -f docker-compose.standalone.yml logs -f
```

Caddy сам терминирует HTTPS для обоих доменов (on-demand TLS: сертификат
выпускается при первом запросе, когда DNS уже указывает на этот узел).
Порт **8083 публикуется на хост** — он должен быть доступен другим узлам.

## Настройка reg.ru

1. В своём аккаунте reg.ru включи **REG.API 2.0** и добавь **публичные IP всех
   узлов** в белый список API (иначе запросы отклоняются).
2. Убедись, что зоны `example.net` и `example.com` обслуживаются в этом аккаунте.
3. Понизь TTL A-записей `admin` и `happ` (например, 300 c), чтобы переключение
   распространялось быстрее.
4. В панели → `/settings` укажи логин/пароль reg.ru и домены, сохрани.

## Как работает фейловер

- Каждые `poll_interval` сек узлы пингуют друг друга. Узел считается мёртвым
  после `fail_threshold` неудач подряд.
- **Активным** должен быть самый живой узел с наименьшим `priority`.
- Если активный мёртв — следующий по приоритету живой узел переписывает A-записи
  обоих доменов на себя. Чтобы не было **split-brain**, по умолчанию требуется
  **кворум** (большинство узлов согласны, что активный мёртв): меньшинство в
  разрыве сети DNS не перетянет.
- **Failback (preempt):** когда вернётся более приоритетный узел, он забирает
  DNS обратно (можно отключить в настройках).
- **Ручное переключение:** в `/cluster` кнопка «Сделать активным» переносит DNS
  на выбранный узел и «пинит» его; авто-фейловер сработает, только если
  закреплённый узел умрёт. «Снять пин» — вернуть авто-режим.

## Панель

- `/` — **нодовый граф**: источники (подписки) → маршруты (твои пути). Слияние
  нескольких подписок в одну, переименование, свои пути.
- `/classic` — то же списком форм.
- `/cluster` — узлы, живость, активный, ручное переключение, журнал, добавление узлов.
- `/settings` — reg.ru, домены, параметры фейловера.

---

## Совместимость

Логика подписок прежняя: режим **зеркало** (один upstream как есть) и **слияние**
(несколько → один base64-список с агрегацией трафика). Легаси-зеркало можно
создать при первом старте, задав `UPSTREAM_URL` + `SUB_PATH`.
Здоровье узла: `GET /healthz` на любом порту → `ok`.
