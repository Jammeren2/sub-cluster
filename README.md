# sub-cluster (бывш. concord-sub-mirror)

Кластер из 3+ узлов, который отдаёт VPN-подписки и сам переживает падение
любого сервера за счёт **DNS-фейловера через reg.ru**.

Каждый узел:
- отдаёт подписки (зеркало одной или **слияние нескольких** в одну, base64-список);
- хранит конфиг в локальной **SQLite** и **синхронизирует** его с другими узлами;
- пингует остальных, понимает, кто живой, и при падении активного **самый живой
  по приоритету** узел переписывает A-запись домена подписок на себя через API reg.ru;
- даёт веб-панель: нодовый граф подписок, узлы с живостью, ручное переключение DNS,
  настройки reg.ru/домена/фейловера.

Домены:
- **admin-домен у КАЖДОГО узла свой и статичный** (`admin.example.net`,
  `admin2.example.net`, …) — панель узла всегда доступна, A-записи прописываешь
  вручную, **reg.ru их не трогает**. Через эти же домены (по 443) узлы общаются.
- **happ.example.com** — домен подписок для клиентов: **единственный, который
  фейловерится** — reg.ru переключает его на активный узел.

## Архитектура

```
  admin.example.net→узел1   admin2.example.net→узел2   admin3…→узел3  (статичные)
            ▼                          ▼                        ▼
        reverse-proxy:443         reverse-proxy:443        reverse-proxy:443
   ┌──────── узел 1 ───────┐  ┌──────── узел 2 ───────┐  ┌──────── узел 3 ───────┐
   │ ADMIN :8080  SUB :8081│  │ ADMIN :8080  SUB :8081│  │ ADMIN :8080  SUB :8081│
   └───────────┬───────────┘  └───────────┬───────────┘  └───────────┬───────────┘
               └── peer-API (HMAC) через admin-домены по 443: живость + синк ──┘
                         (SQLite на каждом; config — LWW, members — CRDT)
        happ.example.com ──reg.ru API──► A-запись на активный (самый живой по приоритету)
```

Ключевая идея: узлы ходят друг к другу через **статичные admin-домены по 443**
(их и так держит reverse-proxy), поэтому **отдельные порты кластера наружу
открывать/пробрасывать не нужно** — это снимает проблемы с NAT и фаерволами.
Фейловерится только домен подписок.

Порты на узле:
- **ADMIN_PORT (8080)** — панель + peer-API кластера (`/cluster/*`, HMAC);
- **SUB_PORT (8081)** — подписки;
- **CLUSTER_PORT (8083)** — необязательный прямой peer-API по IP (фолбэк).

## Переменные окружения (на каждом узле)

| Переменная        | Назначение                                                         |
|-------------------|--------------------------------------------------------------------|
| `NODE_ID`         | Уникальный **постоянный** id узла (не меняй между деплоями!)        |
| `NODE_LABEL`      | Человеческая метка (видна в панели)                                 |
| `NODE_PUBLIC_IP`  | Публичный IP сервера — он прописывается в DNS **подписок** при фейловере |
| `NODE_PRIORITY`   | Приоритет (**меньше = важнее**). Активным становится самый живой с наименьшим |
| `CLUSTER_URL`     | **Свой admin-домен** этого узла (`https://admin2.example.net`) — адрес для пиров |
| `ADMIN_DOMAIN` / `SUB_DOMAIN` | Для Caddy (standalone): admin-домен узла и домен подписок |
| `PEERS`           | admin-домены **других** узлов через запятую (бутстрап; дальше синк сам) |
| `CLUSTER_SECRET`  | Секрет подписи peer-запросов — **одинаковый на всех узлах**         |
| `SECRET_KEY`      | Ключ шифрования секретов в БД — **одинаковый на всех узлах**        |
| `ADMIN_USER` / `ADMIN_PASSWORD` | Доступ в панель (дефолтный/пустой пароль → отказ старта) |
| `DB_FILE`         | Путь к SQLite (в Docker — `/data/cluster.db`, volume)              |
| `CACHE_TTL`       | Кэш ответов upstream, сек (60)                                      |

reg.ru-логин/пароль и домен подписок задаются в панели (`/settings`) **один раз** и
расходятся по кластеру (пароль шифруется `SECRET_KEY`, поэтому ключ должен
совпадать на всех узлах).

## Деплой

Два compose-файла: `docker-compose.yml` — для Coolify (только приложение,
HTTPS делает прокси Coolify), `docker-compose.standalone.yml` — для серверов
без Coolify (приложение + Caddy).

### DNS-записи (один раз, вручную в reg.ru)

- A-запись admin-домена **каждого** узла → IP этого узла (статично, навсегда):
  `admin.example.net → IP1`, `admin2.example.net → IP2`, `admin3… → IP3`.
- A-запись `happ.example.com` → IP любого узла для старта (дальше фейловер ведёт сам).

### Узел с Coolify

Coolify сам поднимает прокси (Traefik) на 80/443, свой Caddy не нужен — деплоится
только сервис `app` из `docker-compose.yml`.

1. Создай ресурс **Docker Compose** из репозитория (файл `docker-compose.yml`).
2. В **Environment Variables** задай (см. `.env.example`): `NODE_ID`, `NODE_LABEL`,
   `NODE_PUBLIC_IP`, `NODE_PRIORITY`, **`CLUSTER_URL`** (свой admin-домен,
   `https://admin.example.net`), **`PEERS`** (admin-домены других узлов через
   запятую), `CLUSTER_SECRET`, `SECRET_KEY`, `ADMIN_USER`, `ADMIN_PASSWORD`.
3. Назначь домены сервису `app`: **свой admin-домен** → порт **8080**,
   `happ.example.com` → порт **8081** (в Coolify: Domains, или `SERVICE_FQDN_APP_8080`
   / `SERVICE_FQDN_APP_8081`).
4. Доп-порты наружу открывать **не нужно** — узлы ходят друг к другу через
   admin-домен по 443.

### Узлы без Coolify (docker compose + Caddy)

```bash
git clone <репозиторий> sub-cluster && cd sub-cluster
cp .env.example .env      # NODE_ID/NODE_PUBLIC_IP/CLUSTER_URL/ADMIN_DOMAIN/SUB_DOMAIN/PEERS/секреты
docker compose -f docker-compose.standalone.yml up -d --build
docker compose -f docker-compose.standalone.yml logs -f
```

Caddy терминирует HTTPS для admin-домена узла и домена подписок (on-demand TLS).
Открыть наружу нужно только **80/443** — отдельные порты кластера не публикуются.

## Настройка reg.ru

1. В аккаунте reg.ru включи **REG.API 2.0** и добавь **публичные IP всех узлов**
   в белый список API (иначе запросы отклоняются).
2. Убедись, что зона `example.com` (домен подписок) обслуживается в этом аккаунте.
3. Понизь TTL A-записи `happ` (например, 300 c) для быстрого переключения.
4. В панели → `/settings` укажи логин/пароль reg.ru и домен подписок, сохрани.

## Редеплой узлов из панели (кнопка «Редеплой»)

На вкладке `/cluster` у каждого узла есть кнопка **«Редеплой»** (если задан вебхук).
Приложение само ничего не пересобирает (в контейнере нет git/docker) — оно **дёргает
redeploy-вебхук узла**. Узел дёргает СВОЙ вебхук (поэтому вебхук может слушать localhost).

Сначала на хостах настрой **git-доступ к приватному репо** (deploy-key или PAT), иначе
`git pull` не пройдёт.

**Узел с Coolify:** в поле «redeploy-вебхук» вставь его **deploy-webhook** из Coolify,
в «redeploy-токен» — API-токен (уйдёт как `Authorization: Bearer`). Coolify сам сделает
git pull + build.

**Узел без Coolify:** запусти на ХОСТЕ агент `redeploy-agent.py` (он делает
`git pull && docker compose -f docker-compose.standalone.yml up -d --build`):
```bash
REDEPLOY_TOKEN='секрет' REPO_DIR=/root/concord-sub-mirror \
  python3 redeploy-agent.py    # слушает 0.0.0.0:9090 (закрой порт извне фаерволом)
```
В панели у узла:
- redeploy-вебхук = `http://host.docker.internal:9090/redeploy`
  (в compose у `app` есть `extra_hosts: host.docker.internal:host-gateway` — контейнер
  достучится до агента на хосте);
- redeploy-токен = тот же `REDEPLOY_TOKEN`.

Токен хранится в БД **зашифрованным** (`SECRET_KEY`) и реплицируется по кластеру.
Кнопка защищена: из UI — сессией, между узлами — HMAC.

## Как работает фейловер

- Каждые `poll_interval` сек узлы пингуют друг друга (через admin-домены по 443).
  Узел считается мёртвым после `fail_threshold` неудач подряд.
- **Активным** должен быть самый живой узел с наименьшим `priority`.
- Если активный мёртв — следующий по приоритету живой узел переписывает A-запись
  **домена подписок** на себя. Admin-домены статичные и не меняются. Чтобы не было
  **split-brain**, по умолчанию требуется **кворум** (большинство узлов согласны,
  что активный мёртв): меньшинство в разрыве сети DNS не перетянет.
  ⚠️ При **2 узлах кворум недостижим** (большинство = 2, мёртвый не голосует) —
  для авто-фейловера нужно **≥3 узлов**, либо отключи кворум в `/settings`.
- **Failback (preempt):** когда вернётся более приоритетный узел, он забирает
  DNS обратно (можно отключить в настройках).
- **Failback (preempt):** когда вернётся более приоритетный узел, он забирает
  DNS обратно (можно отключить в настройках).
- **Ручное переключение:** в `/cluster` кнопка «Сделать активным» переносит DNS
  на выбранный узел и «пинит» его; авто-фейловер сработает, только если
  закреплённый узел умрёт. «Снять пин» — вернуть авто-режим.

## Панель

- `/` — **нодовый граф**: источники (подписки) → маршруты (твои пути). Слияние
  нескольких подписок в одну, переименование, свои пути.
- `/classic` — то же списком форм.
- `/cluster` — узлы, живость, активный, ручное переключение, журнал, добавление узлов.
- `/settings` — reg.ru, домены, параметры фейловера.

---

## Совместимость

Логика подписок прежняя: режим **зеркало** (один upstream как есть) и **слияние**
(несколько → один base64-список с агрегацией трафика). Легаси-зеркало можно
создать при первом старте, задав `UPSTREAM_URL` + `SUB_PATH`.
Здоровье узла: `GET /healthz` на любом порту → `ok`.
