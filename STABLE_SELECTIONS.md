# Сохранение выбора при обновлении VPN провайдером

Раньше ID пункта выбора вычислялся из всей VPN-ссылки/JSON-конфига. Поэтому смена
UUID, пароля, IP, порта или состава балансера делала выбранный пункт новым.

Теперь каталог личного маршрута запоминает соответствие между источником и
именем сервера в БД. При обновлении пользователь получает актуальную ссылку
этого пункта. Сами VPN-ключи в таблицах соответствий не сохраняются.

- Источник определяется по ID ноды графа, поэтому одинаковые имена у разных
  провайдеров независимы. Замена URL подписки в существующей ноде сохраняет ID.
  Удаление и создание ноды заново — новый источник.
- Имя сравнивается после NFC-нормализации Unicode, без учёта регистра и лишних
  пробелов. Флаги, страны, цифры и другие значимые части имени не отбрасываются.
  Имя VMess берётся из `ps`, JSON-конфига — из `remarks`/`ps`.
- Роутер и авто-выбор привязаны к ID ноды целиком. Корзины группы — к ID группы
  и имени корзины, чтобы выбранная группа переживала обновление участников.
- Если в одном источнике обнаружены несколько разных серверов с одним именем,
  они не объединяются. Неоднозначность сохраняется в БД: исчезновение одного
  из одноимённых серверов не даёт оснований автоматически выбрать другой.
- Для безымянных записей и небезопасных открытых списков остаётся точное
  сопоставление. Название страны из открытого списка не идентифицирует сервер.
- Временное отсутствие сервера по-прежнему не удаляет сохранённый выбор.

## Существующие пользователи

Первые наблюдаемые ID сохраняются, а последующие хеши актуальных конфигураций
становятся их синонимами. Сохранённые старые хеши разрешаются через эту таблицу
при выдаче подписки и открытии/сохранении управления. HWID, имена пользователей,
контакты и секреты управления не пересоздаются.

Перенос старого выбора возможен только если соответствующая старая конфигурация
была замечена после обновления приложения. Если провайдер уже заменил её до
первого наблюдения, по старому хешу нельзя восстановить имя: такой пункт надо
выбрать заново один раз. Если провайдер изменил и имя, требуется повторный выбор.

Таблицы `personal_choices`, `personal_choice_aliases`, `personal_ambiguous_choices`
создаются автоматически в текущей БД. На PostgreSQL транзакционная блокировка
защищает одновременную регистрацию с разных серверов; оба приложения должны
работать с одной общей БД и одинаковой версией. В legacy SQLite личный маршрут
по-прежнему обслуживает его владелец. Мигратор SQLite → PostgreSQL переносит
таблицы соответствий вместе с личными ссылками и отклоняет конфликты.
